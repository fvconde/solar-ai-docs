## Preparação do Banco `solar_test` e Execução dos Testes de Integração

A suíte de testes de integração `Solar.Api.Tests.ExclusaoLeadPostgresTeste` valida o comportamento de exclusão em cascata, isolamento entre leads e concorrência multithread com PostgreSQL real.

### 1. Criação do Banco Local
O banco `solar_test` deve existir na instância Postgres local (`localhost:5432`).

Para criar via `psql` / Docker:
```bash
docker exec -i solar-postgres-1 psql -U solar -d postgres -c "CREATE DATABASE solar_test OWNER solar;"
```
Ou no cliente SQL / pgAdmin conectado ao Postgres:
```sql
CREATE DATABASE solar_test OWNER solar;
```

### 2. Configuração de Variáveis de Ambiente
A suíte obtém a conexão da seguinte forma:
1. **Prioritária:** Variável de ambiente `ConnectionStrings__PostgresTest`.
2. **Fallback Local:** Leitura das variáveis `POSTGRES_USER` e `POSTGRES_PASSWORD` do arquivo local `.env` (gitignored), montando a connection string para `Database=solar_test`.

Para configurar via PowerShell:
```powershell
$env:ConnectionStrings__PostgresTest = "Host=localhost;Port=5432;Database=solar_test;Username=solar;Password=<sua_senha>"
```

### 3. Mecanismos de Proteção Ativa
- **Prevenção de contaminação:** A classe `ExclusaoLeadPostgresTeste` inspeciona a connection string. Se o parâmetro `Database` for igual a `solar` (banco de desenvolvimento), ela lança `InvalidOperationException` imediatamente, impedindo que os dados de desenvolvimento sejam afetados.
- **Falha explícita em indisponibilidade:** Caso a conexão não possa ser estabelecida ou ocorra erro durante a execução, o teste aciona `Assert.Fail(...)`, impossibilitando falsos positivos ou skips silenciosos.
- **Aplicação de Migrations:** A cada execução, a classe executa `await dbContext.Database.MigrateAsync()` automaticamente, garantindo que o esquema de tabelas esteja sempre sincronizado.

### 4. Execução dos Testes
Para rodar a suíte completa (62 testes unitários + 3 testes Postgres real):
```bash
dotnet test
```
Para rodar especificamente a suíte de integração:
```bash
dotnet test --filter "FullyQualifiedName~ExclusaoLeadPostgresTeste"
```

### 5. Requisitos para Execução em CI (GitHub Actions)
Nos workflows de CI, adicione um container de serviço Postgres e forneça a connection string:
```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: solar
          POSTGRES_PASSWORD: ${{ secrets.POSTGRES_TEST_PASSWORD }}
          POSTGRES_DB: solar_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - uses: actions/checkout@v4
      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '10.0.x'
      - name: Run Tests
        run: dotnet test --verbosity normal
        env:
          ConnectionStrings__PostgresTest: "Host=localhost;Port=5432;Database=solar_test;Username=solar;Password=${{ secrets.POSTGRES_TEST_PASSWORD }}"
```
