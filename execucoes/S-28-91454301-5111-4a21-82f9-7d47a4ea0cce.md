   - Testa a biblioteca `front.py`: configurações de audiência, fallbacks restritivos, DNS/runtime TLS SNI, template de configuração do Nginx, higienização de cabeçalhos `X-Forwarded-For` / `X-Solar-Client-IP` e comportamento do cache de tokens JWT com expiração e concorrência.
   - **Dependências**: Apenas biblioteca padrão do Python (`unittest`, `urllib`, `concurrent.futures`, `json`, `base64`, `pathlib`).
   - **Execução sem Docker**: Testado localmente via `python -m unittest deploy/tests/test_front.py`.
   - **Resultado**: **17 testes aprovados em 1.58s**, exit code `0`.
   - **Conclusão**: **Roda 100% sem Docker**.

2. **`smoke_docker.py` (Testes de integração de container)**:
   - Realiza validação ponta a ponta dos containers do front em rede isolada.
   - **Dependências**: Invoca comandos diretos do executável `docker` (`docker exec`, redes internas `s26-smoke-*`, containers `s26-backend-*`), exigindo as imagens `solar-ai-front:s26-local` e `postgres:16-alpine`.
   - **Execução sem Docker**: Impossível; falha imediatamente se o daemon Docker ou as imagens pré-construídas não existirem.
   - **Conclusão**: **Exige Docker**.

**Recomendação de CI para o Front**:
Os testes unitários de `deploy/tests/test_front.py` podem ser integrados no CI caso se decida rodar validações de proxy/nginx, dispensando Docker. Já o `smoke_docker.py` deve permanecer fora do pipeline de CI de testes padrão de push/PR por demandar daemon Docker e montagem completa de infraestrutura.
