# Contrato de API do S-44 — Porta de entrada

- Card: S-44 · Porta de entrada: login único, cadastros e conta (Notion `3e43478c-8945-81f5-9f0a-ea3f4c0a78e3`)
- Execução: `0a7099b3-7fe0-4e3b-90e7-81245441c62a`
- Estado: **RASCUNHO do Maestro.** O executor do backend (Codex S-44) revisa, ajusta e congela. Enquanto esta linha disser RASCUNHO, o front não implementa contra ele.
- Dono: backend. Depois de congelado, qualquer mudança de campo exige combinar com o front por `maestri ask` **antes** de alterar, e registrar a mudança na seção "Histórico" no fim deste arquivo.

## Convenções

- Tudo sob `/api`, JSON em camelCase, `withCredentials: true` no front.
- Sessão em cookie `HttpOnly`, `SameSite=Strict`, `Secure` fora de Development, `Path=/`. Um cookie só para os três papéis. O nome é decisão do backend; o front nunca lê o cookie.
- Validade da sessão: 30 dias, renovada com o uso (janela deslizante). O `max-age` de 10 anos sai.
- Erro de negócio: corpo `{ "codigo": "<codigo>", "mensagem": "<texto para log, não para tela>" }`. O front escolhe o texto da tela pelo `codigo`.
- Erro de validação: `400` com `{ "codigo": "validacao", "campos": { "<campo>": "<codigo_do_erro>" } }`. Códigos de campo: `obrigatorio`, `formato`, `curto`, `longo`, `lista_vazia`, `valor_invalido`, `divergente`.
- Papéis: `cliente`, `corretor`, `supervisor`. Status do corretor: `em_analise`, `aprovado`. O supervisor é sempre `aprovado`.
- Regiões aceitas no cadastro: `norte`, `sul`, `leste`, `oeste`, `centro` (uma ou mais). Especialidades: `moradia`, `investimento` (uma ou as duas).
- Regras de campo, iguais no front e no back: nome de 2 a 120 caracteres; e-mail normalizado pelo `NormalizadorDeEmail` existente e **único entre todos os papéis**; telefone com 10 ou 11 dígitos depois de tirar máscara (o back guarda só dígitos); senha com no mínimo 8 caracteres.

## Tipos compartilhados

```ts
type Perfil = 'cliente' | 'corretor' | 'supervisor';
type StatusCorretor = 'em_analise' | 'aprovado';

interface SessaoResponse {
  usuario: { id: string; nome: string; email: string };
  perfil: Perfil;
  statusCorretor: StatusCorretor | null;   // null para cliente
  // Campos que o painel já consome hoje; null/[] para cliente.
  corretorId: string | null;
  vinculoAtivo: boolean;
  filtrosPermitidos: string[];
  filtroInicial: string | null;
  pendentesAprovacao: number | null;       // só supervisor; null para os outros
}

interface ContaResponse {
  id: string;
  nome: string;
  email: string;
  telefone: string;                          // só dígitos
  perfil: Perfil;
  criadaEm: string;                          // ISO 8601
  corretor: {
    status: StatusCorretor;
    regioes: string[];
    especialidades: string[];
    aprovadoEm: string | null;
  } | null;
  consentimento: { em: string; versao: string } | null;   // aceite do cadastro
  conversasSalvas: number;                   // 0 para corretor e supervisor
}

interface ConversaResumo {
  id: string;
  titulo: string;                            // nunca vazio; ver regra abaixo
  atualizadaEm: string;
  estado: 'em_andamento' | 'com_corretor' | 'encerrada';
}

interface CorretorPendente {
  id: string;
  nome: string;
  email: string;
  telefone: string;
  regioes: string[];
  especialidades: string[];
  criadoEm: string;
}
```

## Sessão

| Método e rota | Corpo | Sucesso | Erros |
|---|---|---|---|
| `POST /api/sessoes` | `{ email, senha, conversaId? }` | `200 SessaoResponse` + cookie | `401 credenciais_invalidas` (mesma resposta para e-mail inexistente e senha errada, **sem contador de tentativas**); `423 bloqueado` com `{ codigo, segundosRestantes }`; `429` do rate limit |
| `GET /api/sessao` | — | `200 SessaoResponse` | `401` sem sessão válida |
| `DELETE /api/sessao` | — | `204`, revoga a sessão no servidor e apaga o cookie | `401` sem sessão (o front trata como saída concluída) |

- O bloqueio de 5 tentativas do S-42 continua, com a mesma duração.
- `conversaId` opcional: se vier de uma conversa **sem dono** e quem entra é `cliente`, a conversa passa para a conta, mantendo o consentimento dela. Se a conversa já tiver dono, é ignorado sem erro.
- **Saem:** `POST /api/painel/identificacao`, `POST /api/painel/sessoes` e `GET /api/painel/sessao`.

## Cadastro

| Método e rota | Corpo | Sucesso | Erros |
|---|---|---|---|
| `POST /api/contas` | `{ nome, email, telefone, senha, aceitePrivacidade: true, conversaId? }` | `201 SessaoResponse` + cookie (perfil `cliente`) | `400 validacao`; `409 email_em_uso`; `429` |
| `POST /api/corretores` | `{ nome, email, telefone, senha, aceitePrivacidade: true, regioes, especialidades }` | `201 SessaoResponse` + cookie (perfil `corretor`, `statusCorretor: "em_analise"`) | `400 validacao`; `409 email_em_uso`; `429` |

- `aceitePrivacidade` diferente de `true` é `400` com `campos.aceitePrivacidade = "obrigatorio"`. O back grava data e versão do aviso aceito (a mesma versão vigente da `/privacidade`).
- Confirmação de senha é só do front; o back não recebe.
- Rate limit por IP nos dois, porque `409 email_em_uso` revela a existência da conta (risco aceito pelo usuário no desenho).

## Conta

| Método e rota | Corpo | Sucesso | Erros |
|---|---|---|---|
| `GET /api/conta` | — | `200 ContaResponse` | `401` |
| `PATCH /api/conta` | qualquer subconjunto de `{ nome, telefone, email, senhaAtual, regioes, especialidades }` | `200 ContaResponse` | `400 validacao`; `400 senha_atual_incorreta`; `409 email_em_uso`; `403` se cliente mandar `regioes`/`especialidades` |
| `POST /api/conta/senha` | `{ senhaAtual, novaSenha }` | `204` | `400 validacao`; `400 senha_atual_incorreta` |
| `DELETE /api/conta` | `{ email }` | `204`, encerra todas as sessões e apaga o cookie | `400 confirmacao_invalida` se o e-mail não confere; `403 nao_permitido` para supervisor |

- Trocar `email` exige `senhaAtual`. Trocar e-mail ou senha revoga **as outras** sessões; a atual continua.
- Mudar a atuação do corretor aprovado vale para os próximos leads e não exige nova aprovação.
- Excluir cliente: apaga conta, conversas ligadas a ela e os leads delas, reaproveitando a eliminação do S-29.
- Excluir corretor: apaga a conta; encaminhamentos em atendimento voltam para a fila e são redistribuídos pela `EscolhaDeCorretor`.
- Supervisor não se exclui pelo app (o front esconde o bloco).

## Histórico de conversas do cliente

| Método e rota | Corpo | Sucesso | Erros |
|---|---|---|---|
| `GET /api/conta/conversas` | — | `200 ConversaResumo[]`, da mais recente para a mais antiga | `401`; `403` para corretor e supervisor |

- `titulo`: frase curta derivada do que a Lia já extraiu do lead (intenção, quartos, região), por exemplo "2 quartos na zona sul". Sem dado extraído: "Conversa de <dd mmm>". Nenhuma chamada nova ao LLM.
- `estado`: `com_corretor` quando há encaminhamento; `encerrada` quando há desfecho; senão `em_andamento`.
- **Posse da conversa:** conversa ligada a uma conta só é lida e escrita (`GET /conversas/{id}`, `POST /conversas/{id}/...`) com a sessão dessa conta. Sem sessão ou com outra sessão: `404`, como se não existisse. Conversa sem dono continua funcionando por UUID, como hoje.
- Conversa **nova** criada com sessão de cliente já nasce ligada à conta.

## Aprovação de corretores (só supervisor)

| Método e rota | Corpo | Sucesso | Erros |
|---|---|---|---|
| `GET /api/painel/corretores/pendentes` | — | `200 CorretorPendente[]`, do mais antigo para o mais novo | `401`; `403` |
| `POST /api/painel/corretores/{id}/aprovacao` | — | `204`; envia e-mail pelo `IEnviadorEmail` | `404` se não está pendente; `403` |
| `POST /api/painel/corretores/{id}/recusa` | `{ motivo? }` (até 500 caracteres) | `204`; apaga o cadastro, revoga as sessões e envia e-mail com o motivo | `404`; `403` |

- Corretor `em_analise`: `GET /api/painel/leads` devolve `{ "itens": [], "total": 0 }`, `GET /api/painel/leads/{id}` devolve `404`, e ele não entra na `EscolhaDeCorretor`.
- Corretores semeados antes do S-44 viram `aprovado` na migration.

## Recuperação de senha

Os três endpoints do S-42 mudam de prefixo e passam a valer para qualquer papel, com o mesmo comportamento:

| Antes | Depois |
|---|---|
| `POST /api/painel/senha/recuperacoes` | `POST /api/senha/recuperacoes` |
| `GET /api/painel/senha/recuperacoes/{token}` | `GET /api/senha/recuperacoes/{token}` |
| `POST /api/painel/senha` | `POST /api/senha` → `200 SessaoResponse` |
