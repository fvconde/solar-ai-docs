## Contratos finais API ↔ front

SlotOferecido: id inteiro positivo/long; inicio/fim ISO8601 UTC. Oferta sempre lista, nunca null, com até3 próximos slots livres ordenados. Elegível somente com corretor, contato e sem confirmação; GET recalcula.

POST /conversas/{id}/contato,200:

```json
{"leadId":"11111111-1111-4111-8111-111111111111","oferta":[{"id":123,"inicio":"2026-10-07T17:00:00Z","fim":"2026-10-07T18:00:00Z"}]}
```

GET /conversas/{id} preserva conversaId/perfilLead/mensagens/consentimento e acrescenta oferta no mesmo formato.

POST /conversas/{id}/agendamentos, request:

```json
{"slotId":123}
```

200, AgendamentoDaConversa sem envelope:

```json
{"estado":"confirmado","horario":{"id":123,"inicio":"2026-10-07T17:00:00Z","fim":"2026-10-07T18:00:00Z"},"alternativas":[]}
```

409 de horário ocupado/vencido, ProblemDetails com extensões na raiz:

```json
{"type":"about:blank","title":"horario indisponivel","status":409,"codigo":"horario_indisponivel","oferta":[{"id":124,"inicio":"2026-10-07T22:00:00Z","fim":"2026-10-07T23:00:00Z"}]}
```

Oferta do409 pode ser[]. Outros409:agendamento_ja_confirmado, contato_pendente, corretor_nao_atribuido; não representam perda de horário. Slot inexistente/de outro corretor ou conversa inexistente/inacessível:404. Validação do request:400.

Painel GET /api/painel/leads/{id}: agendamento null quando vazio; confirmado usa inicio/fim persistidos:

```json
{"agendamento":{"dataHora":"2026-10-08T17:00:00+00:00","status":"confirmado","fim":"2026-10-08T18:00:00+00:00"}}
```

Texto fixo neutro da Lia: `Combinado! {corretor} vai te chamar no contato que você deixou.`
